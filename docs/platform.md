# 基盤（GAS・シート・速さ・更新・ログイン・通知・写真）

CLAUDE.md から移した仕様（中身は同じ）。この機能を直す時だけ読む。仕様を変えたらここを直す。

## 仕様
- ウェブアプリ（実行：自分、アクセス：全員）。中身はログインした2人だけに返す
- GASに家族のデータや見本の行を書かない。中身はすべてシートから読む
- 列は1行目の見出しの名前で読む（列の追加・並べ替えOK）。id が空の行は中身から自動のidを付ける
- シート：設定／画面／担当／チェック／申し送り／日記／献立／買い物／予定／中期／ニュース／話題／要望／相談／期限／お出かけ／使われ方／ふりかえり／改善ログ／返信／_sessions／_keys／Museの記録
- 「設定」：クライアントID、人1・人2の呼び名（とと・まま）・別名（カレンダーの予定名の頭など、別の書き方。カンマ区切り）・メール・色、家族の色、子どもの呼び方・誕生日、時間帯、献立がない日の文言、カレンダーID、写真フォルダID。誰の欄は呼び名でもパパ・ママでも通じる
- 「画面」：キー（photos/hero/flow/decide/deadline/topics/diary/week/shop/weekend/plan/news）ごとに見出し・みんなのタブ・人のタブ・順番・夜の順番・旅行中・見る人（空＝2人、人1/人2/呼び名＝その人がログインした時だけ）・下のタブ（アプリ下の切り替え。既定は 今日／ふたりで／ごはん／予定／ニュース。画面での名前は 今日→「ホーム」、ふたりで→「相談・連絡」（app.js の TAB_LABEL）。同じ名前のセクションが同じ画面に出る。中身のないタブは出さない。旅行中は話題を最初のタブへ）
- 速さ：bootの結果をCacheServiceにまとめて置く（10分）。書き込み・手での編集（onEdit）で作り直す。アプリを引っぱると fresh で読み直す
  - まとめの鍵は「組み立てる前の版」。組み立て中に書き込みがあっても古いまとめが新しい版として残らない
  - CacheServiceは1件100KB（バイト）。日本語は1文字最大3バイトなので3万文字ずつに分ける
- 書き込む文字は先頭に ' を付けて文字として入れる（「1/2」が日付に、「=」「-」で始まる文が数式に化けない）
- URLは https だけ返す（ニュース・話題・献立の写真）
- API の版：app.js の `API_EXPECTED` は「画面が必要とする GAS の版の下限」。GAS の `API_VERSION` がそれより古い時だけ画面に知らせが出る。新しい機能は GAS の返す中身（swapsAhead など）があるかで出し分け、画面を先に公開しても壊れないようにする
- スプレッドシートのメニュー「わが家」：アプリに反映／シートを整える（setup）
- アプリから書く：担当（saveDuty/deleteDuty。日付あり＝その日だけ、なし＝曜日でくり返し）、買い物（saveShop/deleteShop）、話題（saveTopic/deleteTopic）、要望（addFeedback）。書く列が無ければ右はしに足す
- 天気：設定「天気の場所」（地名 緯度,経度）、旅行の期間は「旅行先の天気の場所」。GASが Open-Meteo（登録なし）から取り、1時間まとめて置く
- 新しい版の確認：アプリに戻った時と、引っぱって更新した時に Service Worker を確かめる（ホーム画面のアプリは戻っただけでは読み直さないため）。新しい版が入ったら controllerchange で読み直す（入力中・ホーム以外のタブなら次に戻った時）
- 開いた時（起動・アプリに戻った時）は openRefresh：手元のデータが前の日なら「更新中」を出して読む。起動時・前に読んでから3分以上・日が変わった時は fresh（GAS のまとめを作り直す）、それ以外はまとめで速く
- 新着：前に見た時の中身（端末の localStorage `seen`）と比べ、相手が足した・変えたものに「新着」。自分の書き込みは印にしない（返信・コメントも、数えるのは相手が書いた物だけ。sigsOf）。アプリを閉じると見たことになる
- 相談の添付：シート「相談」の列「添付」に JSON（`[{id, t:'i'|'p', n}]`、API 21から10まで、20までは3つ）。置き場は写真とは別の「WAGAYA 添付（アプリから）」（スクリプトのプロパティ `attachFolder`。スライドに混ざらない）。addAttachment（画像8MB・PDF5MBまで）・attachData（置き場の中の物だけ返す）。saveDecision の files を送らない古い画面は添付を消さない。画面は編集を開いた時の一覧 files0 も送り、GASは「files0 にあって files に無い物」だけを外した扱いでごみ箱へ入れる（開いている間に相手が足した物は残す）。消した相談の添付もごみ箱へ（置き場の中の物だけ）。添付は週1回のバックアップに入らず、ごみ箱の物は30日で消える。boot には id・種類・名前だけで、中身は入れない。API 20。詳しい画面側は docs/talk.md
- 写真を足す：写真の見出しの右上のボタン（カメラ＋）から、iPhoneの写真を選んで送る（20件まで）。写真は画面で長い辺1600pxのJPEGに縮める。動画は15MBまで（設定「動画の上限MB」を超えるとGASが断る）。GASの addPhoto が、自分で作った置き場「WAGAYA 写真（アプリから）」（スクリプトのプロパティ `uploadFolder`。drive.file の権限で書けるのは自分で作ったフォルダだけのため）に入れる。写真の一覧は「写真フォルダID」と置き場の両方から、みてねのように最近足した物（ドライブに入った日が設定「写真を出す期間（日）」既定30日以内）を新しい順に最大30件。少ない時は古い物で8件まで埋める（GAS の pickRecent）。画面は1コマ目を8枚ずつ取り、動画の中身は新しい5本だけ取る。iCloud共有アルバム→パソコン→ドライブの自動の流れはやめた（ARMのパソコンでiCloudが不安定・再起動で共有アルバムのフォルダが消える不具合の報告があるため）
- 写真フォルダの動画：上限（設定「動画の上限MB」、既定10・最大15）以下は中身を取って端末に保存してスライドで再生。超えたら1コマだけ
- 学ぶ仕組み：アプリが「使われ方」を回数だけ記録（open/tab/sec/act/err。文章は残さない）→ 金曜21時に weeklyReview が「ふりかえり」に1行 → 持ち主に「ふりかえりして」と言われたら、使われ方・ふりかえり・要望を読み、改善案を「改善ログ」に書いて提案 → 選ばれたものを直す → 次の週に結果を「改善ログ」に書く
- バックアップ：日曜3時に backupNow がシートをドライブのフォルダ「WAGAYA DB バックアップ」へ丸ごとコピー（8週分）。drive.file の権限を使う
- すぐ反映：開いている間は15秒ごとに action:'ver'（版だけ）を確かめ、変わった時だけ boot で読み直す。5分ごとには必ず読み直す（カレンダーなどシートの外の変更のため）
- 通知（Web Push。ホーム画面のアプリだけ、iPhoneは iOS 16.4 以降）：アカウントのシートの「この端末で通知を受け取る」（押したその場で許可を聞く）・「テスト通知を送る」・「オフにする」。届くのは ①自分宛ての申し送り（代わってほしいの頼みと、その答えも）②相手からの返信・コメント ③相手が相談を足した・答えた時。自分の書き込みでは鳴らない。設定「通知を止める時間」（既定 22:00〜6:00）の分は貯めて、明けたら pushTick（1時間ごと）でまとめて送る。止めている間にアプリを開いたら、その分は送らない
  - 中身は送らない：GAS は空の合図だけ送り、sw.js がログインの控え（Cache Storage `wagaya-auth` の `./__auth`。g＝GASのURL）で action:'pushPeek'（endpoint つき＝端末ごとに渡した印）を聞いて出す。聞けなくても必ず1つ出す（iPhone は出さないと受け取りを止める）。続けて来た分は、端末がまだ聞きに来ていなければ2回目を送らず1回でまとめる
  - 鍵（VAPID、P-256）は GAS の vapid() が初回に作り、秘密の方はスクリプトのプロパティ `vapidPrivate` だけ（コード・シートに書かない）。JWT は ES256（BigInt、k は RFC 6979。テストで RFC の答えと照合）。届け先は `push:subs`、人ごとの列は `push:q:…`、最後の送信結果は `push:last`。届け先は Apple・Google・Mozilla・Microsoft の通知の場所だけ受け付け、404・410 は自動で外す。ログアウトでその端末の登録も消す
  - 押すとアプリを開いてその場所へ（?go=notes なら申し送り、decide などはそのセクション）。ホーム画面のアイコンの数字：閉じている間は sw.js が「最後に開いてから来た通知の数」（pushPeek の badge。開いた時刻は boot で `push:open:…` に残す）、開くとアプリが「相談・連絡」タブのバッジと同じ数に直す（setAppBadge。0なら消す）
- 「要望」シート：アプリの「要望・不具合を書く」から入る。持ち主に「要望を見て」と言われたら、内蔵ブラウザでこのシートを読んで直し、状態を更新する
- ログイン：Googleの id_token をリダイレクトで受け取り（ポップアップなし）、GASが tokeninfo で確かめ、設定の2人なら180日のセッションを発行（_sessionsにはハッシュだけ保存）
- 手元からログインが消えた時：①同じ端末の Cache Storage `wagaya-auth` の控えから戻す ②だめなら Google に prompt=none（画面なし、login_hint 付き）で1回だけ確かめる ③それもだめならログイン画面。Googleから戻った直後とログアウト後（localStorage `loggedOut`）は自動で行かない。サーバーが断った時（no_session）は控えも消す
- 調べるための記録（使われ方、回数だけ）：diag:lost_ls_only（localStorageだけ消えた）／lost_ls_and_auth／lost_all、restored、silent_ok／silent_ng、login_ok、persist_yes／no
